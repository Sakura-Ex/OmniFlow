# 工作区、侧栏与配方页面实施方案

状态：工作区、对象浏览与属性迁移已实现；配方管理与生成保留规划。更新：2026-10-24。

本文维护工作区结构、阶段边界及未来配方页面的实施依赖。交互契约以[交互手册](interaction-design-handbook.md)为准，计算语义以[技术设计手册](technical-design-v2-proposal.md)为准。已确认的行为同步到手册，本文不另设相互冲突的交互规范；验证覆盖以[测试指南](testing.md)为准。

## 1. 目标与范围

让几十台机器的产线易于浏览、定位与编辑，同时给未来的配方批量导入和产线生成留出清晰位置。

- 左侧负责对象浏览；中央负责主要工作内容；右侧负责当前对象的完整编辑。
- 配方管理是与产线并列的工作页面，不挤入机器属性侧栏。
- 左侧将来可以表达工段层级，现在只展示平铺对象，不创建分组数据或空的层级控件。
- 机器数量、最终交付产率、异常和计算状态继续突出；取消横贯画布的结果底板。
- 复用已完成的三种节点显示模式、设置分区、资源行、单位展示与编辑事务。

本阶段范围为工作区、浏览与编辑，配方页面只保留禁用入口。配方导入、自动生成、工段分组、语义缩放、通用批量修改、网络追踪和方案对比仍需分别设计和授权。计算模型、求解器和业务规则不属于布局迁移范围。

## 2. 当前结构与责任

| 代码 | 当前责任 | 维护边界 |
|---|---|---|
| `src/App.tsx`、`src/app/workspace/` | 应用组合、侧栏开合、选择联动、定位与返回、草稿离开协调 | 保持 ReactFlow 实例挂载；领域数据不复制到工作区状态 |
| `src/app/components/MenuBar.tsx` | 菜单、计算入口等 | 布局菜单控制左右栏；侧栏顶部标签切换内容 |
| `src/app/components/SettingsPage.tsx` | 本机偏好、产线与网络、资源、单位设置 | 保持完整设置页；复用其中适用的领域编辑内容 |
| `RecipeEditor.tsx`、`EndpointEditor.tsx`、`src/app/editors/` | 右侧配方／端点编辑与统一提交 | 旧弹窗容器已移除；领域表单和应用事务职责分离 |
| `NetworkConfigurationEditor.tsx`、`planningDraft.ts` | 全局及当前机器的规划设置、基线冲突检测和作用域合并 | 侧栏与全局设置共用表单；单机保存不得覆盖其他节点策略 |
| `ObjectBrowser.tsx`、`objectBrowser.ts` | 从权威节点和资源派生平铺列表与搜索内容 | 只执行显式选择／定位，不建立第二份图或层级模型 |
| `CoreResultSummary.tsx`、`SystemHUD.tsx`、`resultEvidence.ts` | 左下摘要与资源／设备明细，共用求解时的名称和单位证据 | 容器开合及当前条件变化不能重新解释旧结果 |
| `useDocumentSession.ts`、`DocumentEditContext` | 保存身份与编辑事务 | 作为持久化、撤销和计算失效的唯一既有路径 |
| `recipe.store.ts` | 以节点 ID 关联配方数据 | 不直接冒充未来的可复用配方库 |

以上文件除标注完整路径者外，位于各自 `src/features/` 领域目录。三种显示模式沿用现有实现，工作区迁移没有新增一套节点组件或计算模型。

## 3. 信息架构

### 3.1 工作页面与页面内部布局

左侧栏顶部以相连标签呈现**产线｜配方**的页面位置，与“文件、编辑、添加”等命令菜单区分。当前只提供产线工作区；配方入口禁用，不提供可进入的空页。

| 区域 | 产线页面 | 配方页面（未来） |
|---|---|---|
| 左侧 | 当前文档对象列表、查找入口；以后扩展工段层级 | 配方集合、来源、分类与搜索 |
| 中央 | 产线画布 | 配方表格、导入校验与生成预览 |
| 右侧 | 当前机器、供应、目标或其他受支持对象的属性 | 当前配方详情或当前生成步骤的配置 |

左侧回答“有哪些、在哪里”，右侧回答“这个对象是什么、怎么改”。这种分工是设计判断，不是左右位置具有普遍认知优势的实验结论。两侧均可收起，不强制永久占用画布宽度。

### 3.2 左侧对象浏览

- 当前列出文档真实节点，显示名称、类型、稳定 ID 和必要异常标记；不把机器节点数当作安装机器总数。
- 列表与画布使用相同对象 ID 和选择来源，不维护第二份节点模型。
- 单击只选择；行末独立定位按钮改变视野，避免每次选择都跳动画布。连续定位保留首次定位前的视野，返回后清除此记录。
- 搜索按名称、节点／配方 ID、资源 ID 与显示名过滤整个对象列表，支持多个关键词；不隐藏实际画布节点或改变选择。文档替换后清除查询和返回记录。
- 将来增加层级时再定义父子关系、跨组连接和分组事务。现在可以隔离列表行与容器职责，但不提前增加 `parentId`、空组或复杂树存储。

### 3.3 右侧属性

| 选择状态 | 内容与行为 |
|---|---|
| 未选中 | 简短提示选择对象；不要静默切成全局产线设置 |
| 单台机器节点 | 配方、数量与运行／安装约束、供应、修饰器等现有分区 |
| 单个供应或目标节点 | 复用资源、数量、供应／交付／排放策略编辑 |
| 分流器等其他节点 | 复用其已有能力，不为填满侧栏新增业务设置 |
| 多选 | 显示数量与类型概况；通用批量编辑未实现前不提供伪批量表单 |
| 单条连线 | 仅展示已有可确认的信息，不虚构逐边运输流量 |

保留节点内高频数量编辑和快捷键。显式点击节点设置入口时打开右侧并聚焦相应分区；普通选择只更新已展开面板，不强行展开已关闭面板。复杂配方内容采用分区滚动或明确的扩展编辑入口，不能把现有表单机械压缩到窄栏。

### 3.4 核心摘要与详细结果

采用画布左下角紧凑摘要块，展示机器安装总数、交付摘要及计算状态；点击向上展开详细结果。它独立于左右侧栏开合，不重新加入横贯屏幕的背景条。前两项交付常驻，其余在详情查看；详细内容内部滚动，缩放控件保留在右下角。

- 多交付资源逐项显示，容量不足时显示可展开入口；不合并不同量纲。
- 排放独立于交付，不计入最终产率。
- 未计算显示未知值；没有交付目标明确显示无目标，不填入虚假零值。
- 运行量与安装量分别表达；过期或失败后的旧结果必须保留其归属和状态。
- 摘要、详细结果和节点消费相同结果证据，不能用当前配置重新解释旧结果。
- 详细结果可以关闭，但核心产率、机器数量和状态仍可访问。未来配方页面不把产线结果伪装成本次导入的结果。

## 4. 编辑、焦点与视图契约

### 4.1 草稿和提交

完整属性编辑继续采用显式保存；节点内联操作保留既有提交方式。不能借容器迁移把整个表单改为即时生效。

切换对象、关闭面板、切换工作页面或打开另一文档时，如有未保存草稿，应提供保存、放弃、继续编辑。校验失败则留在原编辑对象并定位错误，不能部分写入。取消切换时恢复原选择和焦点。保存后整次编辑形成一个撤销单元，沿既有事务路径标记结果过期。

同一对象若可从内联入口和属性表单同时修改，必须检测草稿基线是否已变化，不能用旧草稿覆盖新值。优先提示重新载入或取消本次提交，不在布局阶段引入自动字段合并。

### 4.2 布局与响应式

侧栏顶部使用相连的标签页：左侧为“产线／配方”（配方暂不可用），右侧为当前对象的设置分区。标签切换保留草稿保护；左右方向键及 Home／End 移动标签焦点，Enter／空格确认切换。左右栏开合集中在菜单“布局”中，以勾选显示当前状态；侧栏自身保留关闭入口，关闭后可从“布局”找回。不再单独设置画布上的侧栏按钮工具条。

- 两侧栏占满工作区高度并延伸到窗口顶部；菜单与计算入口浮在中央画布上，不另占全宽顶栏或预留顶部空白。菜单按实际可用画布宽度响应，窄屏覆盖式侧栏位于画布浮层上方。
- 开关面板、调整宽度、选择节点、切换语言或工作页面不改节点坐标、连线和计算条件，不触发自动排布或自动适应视图。
- 保留已有画布视野；容器尺寸变化只改变可视面积。真正的定位操作必须由用户触发。
- 宽屏可同时展开两侧；宽度不超过 1100px 时一次只展示一个覆盖式面板。窗口缩窄优先保留右侧属性，主动切换覆盖面板执行草稿保护。
- 面板分别滚动，页脚保存操作保持可达；长名称、多个资源及修饰器不能撑大整个页面。
- 面板开合按钮提供中英文可访问名称。Escape 按最内层关闭，输入框中的删除、撤销不传给画布。
- 右侧提供显式扩展／收窄按钮，当前不支持拖拽调宽。扩展不重新挂载表单或丢失草稿。

## 5. 状态归属与实现边界

### 5.1 状态分类

| 数据 | 所有者与保存策略 | 计算影响 |
|---|---|---|
| 节点、连接、配方实例、边界、环境 | 现有领域 store 与文档事务 | 按现有语义决定失效 |
| 节点显示模式 | 现有文档 `ui` 字段，兼容旧文档 | 不影响计算身份或结果 |
| 左右面板开合 | 本机 UI 偏好；读取时校验，窄屏限制同时展开的面板 | 不进入文档历史，不标记文档修改 |
| 当前选择、查询、临时定位、编辑区扩展 | 会话状态；文档替换时清理无效引用 | 不影响计算 |
| 属性草稿与校验错误 | 编辑会话；绑定对象 ID 和编辑基线 | 提交前不影响模型 |
| 求解结果及其对应条件 | 既有计算结果生命周期 | 不因布局卸载而丢失 |

本阶段不因侧栏新增文档格式版本。旧文档按当前显示模式兼容路径加载；不得将面板偏好加入求解摘要或计算身份。未来配方库若持久化，须单独定义格式、迁移和失败恢复，不能复用节点 ID 作为配方库主键。

### 5.2 组件和调用方维护规则

1. 在 `src/app/` 定义工作区壳层，负责页面、侧栏与草稿切换协调；领域组件不直接操纵全局面板。
2. 从现有弹窗提取编辑内容及草稿逻辑，容器只处理尺寸、焦点和关闭行为。保存、校验、资源行和修饰器不复制实现。
3. 节点设置按钮、菜单、快捷键通过相同的编辑入口指定对象和分区；迁移全部调用方后移除被替代的旧弹窗路径。
4. 左侧列表从画布数据派生；右侧读取相同领域数据，提交经过既有命令／事务。
5. 摘要与详情复用结果证据和数量行；证据随被接受的计算结果保存，不依赖展示组件是否挂载。旧顶部摘要定位已移除，不为摘要预留全宽空白。
6. 保持模块依赖符合现有 lint 边界。跨领域编排放在应用层，只把真正通用的控件放入 `src/common/`。

## 6. 未来配方页面的实施契约

预期流程：**导入 → 校验 → 选择配方与范围 → 生成预览 → 创建新产线／加入当前产线**。

- 导入只进入待校验数据，用户确认生成前不修改当前画布。
- 校验应覆盖资源身份、单位、重复定义、缺失字段和引用关系；定位到行或条目，并允许修正后重试。
- 配方定义与机器实例分离。建议生成时复制经验证的配方快照并记录来源，之后更新配方库不自动改写已有机器；是否支持显式升级另行设计。
- 预览列明将新增的机器、连接、供应和目标，以及尚未解决的选择；不能把同名资源直接合为同一网络。
- 明确区分“把所选配方放入画布”和“从目标反推供应链”。后者涉及替代配方、循环、外供边界和停止条件，须独立设计，不能借 UI 自动补出业务规则。
- 加入当前产线必须整体校验、一次提交、一次撤销；失败保留原文档。创建新产线执行现有文档替换保护。
- 自动布局只作用于明确预览的生成内容，不暗中移动已有节点；接入已有网络必须明确展示连接目标。
- 导入格式、重复项策略、配方库保存位置、来源版本和生成策略均为未来决策，不在侧栏阶段建立占位数据模型。

## 7. 分阶段实施与完成条件

| 阶段 | 交付范围与当前状态 | 验收／启用条件 |
|---|---|---|
| A：布局决策 | 第 9 节方案已获确认 | 宽／窄屏、长表单及草稿流程走查；截图仅放 `artifacts/` |
| B：工作区与属性迁移 | 已实现左侧平铺列表、右侧对象编辑、紧凑摘要及统一编辑入口 | 各类节点现有能力仍可达；无并行旧编辑路径；布局不改变计算与坐标 |
| C：浏览与结果辅助 | 已实现搜索、独立定位与返回，摘要共用设备／交付／排放明细；清单筛选排序仍为规划 | 核对选择与定位分离、旧结果证据、量纲与交付／排放区分；不捆绑网络追踪 |
| D：配方管理与生成 | 规划；仅保留禁用入口 | 先确认配方身份、持久化和生成规则并另行授权；不得只交付文件上传入口 |
| 后续独立议题 | 工段层级、有证据的诊断、方案对比、通用批量操作 | 分别明确语义、收益和验证任务，不作为本次顺带工作 |

阶段 B 不依赖阶段 D。层级扩展也不应阻塞当前平铺浏览。每阶段只更新相关手册、测试和必要使用说明，不新增任务日记或验收报告。

## 8. 验证方案

自动回归优先扩展既有文档、编辑和计算生命周期测试，不为每个样式创建测试：

- 面板和页面切换不修改文档脏状态、计算身份、结果状态及图结构。
- 对象切换中的保存、放弃、取消及校验失败行为一致；草稿基线冲突不覆盖新修改。
- 节点入口与侧栏入口提交相同模型，撤销／重做完整恢复；删除正在编辑的对象不会提交到其他对象。
- 旧文档、新文档及异常本机偏好的恢复有明确回退；三种显示模式保存约定不退化。
- 未来生成操作原子提交，失败无部分模型，撤销恢复包括连接、配方和边界在内的全部变更。

浏览器验收要求覆盖：小型与几十台机器产线；各类节点；长名称、多资源、多修饰器；中英文；宽屏与窄屏；三种显示模式；端口连接；就地编辑；键盘与焦点；草稿切换；面板开合前后视野；计算前后节点尺寸；旧结果保留；保存与重新打开。此清单是要求，实际完成范围见测试指南。

交付时分别报告自动检查和实际浏览器验证，不以构建成功替代交互验证。可用性走查重点观察找到对象、调整数量、读出交付产率、返回原位置四项任务；不把少量走查当作统计效果证明。

## 9. 已确认的产品决策与未来边界

以下方案已获用户确认并用于当前工作区：

| 决策 | 当前方案 | 持续验证的取舍 |
|---|---|---|
| 核心结果位置 | 画布左下角紧凑摘要，点击向上展开详情 | 多交付资源容量；与缩放控件及属性面板的位置关系 |
| 侧栏与菜单布局 | 侧栏全高；菜单浮于中央画布，不额外预留顶部空白 | 按实际画布宽度响应；覆盖式侧栏保持优先层级 |
| 初次进入侧栏状态 | 左侧展开，右侧由显式设置入口打开；之后记忆本机开合偏好 | 浏览面积与设置可发现性 |
| 左侧定位手势 | 单击选择，独立定位按钮 | 多一个入口，但避免选择时视野跳动 |
| 窄屏策略 | 单个覆盖式侧栏，缩窄时优先保留属性草稿 | 在表单可读性和画布可见性之间取舍 |
| 长配方表单 | 右侧分区编辑，必要时显式扩展 | 保留原有分区理解，避免压窄四宫格或复制完整编辑器 |

配方格式、库保存方式和自动构建规则留到阶段 D 开始前确认。当前已经明确的方向是左右分工、机器完整设置可进入右侧、未来支持层级但现在不实现层级。

## 10. 设计依据

沿用[交互手册 §2.2 与 §18](interaction-design-handbook.md#18-参考文献与维护规则)的研究范围：认知维度 [R1] 用于检查修改阻力、可见性和隐藏依赖；RelEx [R3] 支持联动视图的工程设计思路；分层验证模型 [R2] 要求先确认任务与数据，再验证交互；Whyline [R8] 启发从结果问题定位相关条件。

这些研究不证明左侧导航、右侧属性是普遍最优布局，也不证明自动生成、折叠层级或任何特定侧栏宽度有效。本方案是针对 OmniFlow 的设计推断，必须通过上述任务验证。
