# OmniFlow 技术设计修订方案 v2

状态：v2 计算链已实现，使用显式网络编译器和版本化稀疏 LP；旧业务节点求解路径已删除。当前限制见[实现差距](v2-code-gap-assessment.md)，验证方法见[测试指南](testing.md)。

## 1. 产品定位与交付边界

OmniFlow 第一版提供“固定工况下的稳态产线规划”：用户决定配方、机器档位、修饰器配置和物流连接，系统优化各配方的等效满负荷运行量与物流速率。

核心承诺：

1. 每个内部物流网络守恒，资源不能因漏接线而凭空出现或消失。
2. 所有无限供给、允许排放、概率期望等假设均显式可见。
3. 优化按明确的目标优先级执行，不依靠巨大权重模拟优先级。
4. 连续运行量是求解结果；整数安装台数是带条件的安装建议。
5. 求解状态、物理可行性、启动条件与整数安装建议分别报告。

第一版不承诺：自动选择机器档位、最优整数建厂成本、启动过程可行性、库存随时间变化、每条连线的运输能力，以及概率产量的短期保证。

保留 React Flow、前端编译、FastAPI 和 SciPy/HiGHS 的技术路线。暂不实现 SCC 顺序求解。

## 2. 固定产品决策

| 议题 | 第一版决策 |
|---|---|
| 连线含义 | 端口属于同一理想共享管网；箭头表达端口输入输出方向，不承诺边流量 |
| 缺失输入 | 默认阻止编译；可显式改为外部供应 |
| 无出口产物 | 默认不得排放；可显式允许排放 |
| 全局总线 | 只聚合指定端口，不自动创造供应或需求 |
| 目标 | 至少交付、恰好交付、最大化交付；排放作为独立策略 |
| 配方变量 | 等效满负荷运行台数，可为非负实数 |
| 并行与超频 | 用户固定配置后编译成常量，不由 LP 选择 |
| 机器数上限 | 用户输入整数安装容量；运行量不得超过它 |
| 电力 | 区分可调度实际发电、可用容量、持续用电，不把空闲容量当作废物 |
| 外部资源成本 | 默认不宣称最省原料；只有显式配置的供应成本参与对应目标 |
| 求解入口 | 后端接收已经编译好的通用稀疏 LP；不重新推断图业务语义 |

## 3. 资源、端口与单位

### 3.1 三种独立身份

- `resourceId`：资源身份，例如 `mod:item:iron_plate`。包含命名空间，避免插件冲突。
- `portId`：节点内部稳定端口身份，不能使用数组下标；例如 `recipe.input.ore`。
- `netId`：物流网络身份，矩阵行按它索引。相同资源可以存在于多个互不连通的 Net。

每个 Net 恰好对应一个 resourceId。连接不同资源或不可换算量纲的端口应在编译前报错。跨资源转换必须经过配方或显式转换节点。

### 3.2 注册表

资源至少记录：`resourceId`、名称、显示类别、数学类型、标准单位、显示单位换算比例。

数学类型：

- `flow`：可参与加和守恒的通量，包括物料流与能量流。
- `capacity`：可加和的服务能力，通过专用容量约束建模，不能仅凭 UI 类别推断。
- `state`：温度、维度、等级等固定工况条件，不进入物流矩阵。

显示类别只控制图标、颜色和默认展示。K、J、W、N·m、RPM 不得当作同一物理量的显示别名。模组抽象量如 SU 必须由插件明确其可加和与约束语义。

### 3.3 时间基准

环境配置包含 `ticksPerSecond`，且必须为有限正数。

| 输入基准 | 标准化公式 |
|---|---|
| 每周期 | amount × 单位换算比例 / durationSeconds |
| 每 tick | amount × 单位换算比例 × ticksPerSecond |
| 每秒 | amount × 单位换算比例 |

标准化只统一计量基准，不消除量纲。内部保存完整浮点精度；显示时才格式化。

概率输出、工具损耗分别由固定语义字段计算期望值，不能随修饰器拖拽而重复应用。零损耗催化剂保留库存占用数据，流量为零。

## 4. 编译流程与中间表示

唯一编译链：

```text
DocumentSnapshot
→ 数据与环境校验
→ 创建原始节点上下文
→ 按合法依赖顺序执行修饰器
→ 得到最终端口集合、状态资格、BOM 占用
→ 标准单位与每秒归一化
→ 校验失效连线和端口策略
→ 编译 Wired / Global Net
→ 构建变量、守恒、容量、目标
→ 生成稀疏 LP + 来源映射
```

### 4.1 修饰器约定

采用单一接口：`evaluate(readonlyContext, uiState) -> ModifierEffect`。

Context 包含四组 IO、周期、当前固定工况及已完成步骤。Effect 包含数值修改、端口增删、停机原因、BOM 占用变化和说明。由管线统一应用 Effect，插件不得再次原地修改 Context。

每个修饰器声明：版本、适配机器、配置 schema、前置依赖和影响范围。执行必须确定、无网络与时间依赖、受步骤上限约束。相同输入与版本应生成相同结果。

UI 只允许合法重排。若游戏规则要求“先并行后超频”，插件声明依赖，而不是让用户自由构造不符合规则的工况。

并行不能无条件放大全部 IO。每项效用显式声明其缩放依据：每并行槽、每运行机器、每安装机器或每周期。

新增动态端口必须有确定的 portId。端口被删除时，关联连线标记失效，阻止求解并给出修复入口；不得自动移接至其他同名端口。

### 4.2 编译 IR

前端保留以下数据，不因发送矩阵而丢弃：

- 变量索引 → 节点、变量类型、单位。
- 约束行 → Net 或容量池、相关端口、约束含义。
- 每个端口的独立每秒输入或输出系数。
- 每个资源的原始定义、修饰器轨迹和 BOM 占用。
- 模型版本、图版本、插件版本及确定性编译指纹。

同一 Net、同一变量的重复系数必须相加；输入与输出相减得到净系数，但端口毛流量仍保留用于展示。不同 Net 的同名资源绝不能合并。

## 5. 网络与边界策略

### 5.1 Wired 与 Global

Wired 仅联合显式连接的端口。不得因端口属于同一机器就自动联合。Global 按 `scopeId + resourceId + busId` 聚合，支持同种电力的多个独立总线。

Global 端口第一版不允许同时参与 Wired 连线；需要切换模式或使用显式桥接节点。

同一 Net 是理想共享池。若未来需要边容量、运输损耗或严格路径，应引入边流量变量，不能直接沿用共享池语义宣称已支持。

### 5.2 未连接端口

| 端口 | 默认行为 | 用户可选行为 |
|---|---|---|
| 正流量输入 | 编译错误：缺少来源 | 连接 Source，或在配方输入上开启可见的外部供应，无需供应节点与连线 |
| 正流量输出 | 建立独立 Net，禁止排放，可能迫使该机器停机 | 连接消费者/Target，或开启允许排放 |
| 零流量催化剂 | 不参与物流连线要求 | 进入 BOM 与启动占用提示 |

允许排放是显式的 Net 边界配置，包含容量、代价和资源身份。若用户在 UI 对某一输出开启排放，应提示该出口可以接收所在共享 Net 的同种资源。

配方输入的“供应充足”保存为该端口的 `source` 边界，`capacity: null`，也可填写有限上限。编译保留配方消耗项并加入外供变量，实际用量计入外部输入汇总。如果端口已连线或属于全局总线，外供作用于整个共享 Net。“未连线输入均设为供应充足”仅批量配置未连线、未设边界的普通 Wired 正流量输入，不更改库存、容量、工况、全局总线或已有约束。此入口不改变未声明外供时的严格编译行为。交互兼容约定见[交互设计手册](interaction-design-handbook.md)。

没有消费者的封闭产物 Net 必须保留守恒行，不能以“没有 Target”为由删除。

## 6. 连续 LP 模型

### 6.1 变量

| 变量 | 含义 | 边界 |
|---|---|---|
| x_j | 配方等效满负荷运行台数 | 0 ≤ x_j ≤ U_j |
| s_k | 外部输入速率 | 0 ≤ s_k ≤ C_k |
| t_l | 产品交付速率 | 由目标模式指定 |
| w_n | 显式允许的排放速率 | 0 ≤ w_n ≤ W_n |
| f_h | 分流器通过速率 | 0 ≤ f_h ≤ F_h |

无上界使用协议中的 `null`，不传 JSON Infinity。分流器与 Source 速率均不取整，也不收取默认机器台数成本。

### 6.2 守恒

对于每个 flow Net n：

```text
Σ a[n,j] x[j] + Σ source[n,k] s[k]
− Σ target[n,l] t[l] − w[n] + Σ splitter[n,h] f[h] = 0
```

禁止排放的 Net 不创建 w。不存在“没有生产项就跳过约束”的分支。

仅当行与右端项都严格为零时才可作为冗余行移除，并保留诊断映射。非零需求绝不能因零系数而被删除。

### 6.3 目标模式

| 模式 | 变量边界 | 是否加入优化目标 |
|---|---|---|
| 至少交付 d | d ≤ t ≤ 可选上限 | 默认无 |
| 恰好交付 d | t = d | 无 |
| 最大化交付 | 0 ≤ t ≤ 可选上限 | 是，按优先级最大化 |
| 普通产品出口 | 0 ≤ t ≤ 可选上限 | 默认无 |

减少副产物必须选择“减少生成量”还是“减少排放量”。前者使用保留的输出端口毛流量表达式；后者使用 w。不得通过减少某个产品出口伪装成减少生成量。

### 6.4 容量与基建消耗

固定供给能力使用不等式：`Σ load[j] x[j] ≤ availableCapacity`。

可调度发电机的发电量进入电力守恒 Net，运行变量可以低于安装容量；未使用的发电能力不是排放。必须持续运行的发电或不可避免的副产电，则按实际产出建模，并要求合法去向。

第一版对电压等级、温度等采用用户固定工况。若门槛依赖待求解的变量，编译器必须提示超出支持范围，不能提前假定已满足。

按安装机器持续发生的消耗，仅在用户已固定安装数时作为常量负荷加入约束右端项。自动安装模式若遇到此类负荷，要求固定安装数或明确启用近似模式；不得按连续运行量冒充精确计算。

### 6.5 分流器

输入 Net 系数 −1，各独立输出 Net 系数为 ratio，比例非负且总和在校验容差内为 1。

第一版语义为固定比例分配。没有合法去向的支路会限制整体吞吐；只有用户开启排放才可丢弃该支路物料。其他外供、旁路或排放存在时，不承诺下游消费比例。

编译时拒绝输入与输出同 Net、多个输出同 Net 的退化分流器，要求用户先修复接线。共享池下也不承诺边级流向分解。

## 7. 优化策略：显式分层求解

先建立所有硬性约束，再按用户优先级依次求解。

建议默认顺序：

1. 用户配置的产品产出目标，按优先级分组。
2. 用户配置的减少排放、资源成本等目标。
3. 最小化配方等效运行台数。

无最大化目标时，直接进入后续目标。排放若绝对禁止，必须用硬约束，不能依赖目标排序。

统一把每层写成最小化 `g_p(x)`。取得最优值 z_p 后，追加：

```text
g_p(x) ≤ z_p + absTolerance_p + relTolerance_p × |z_p|
```

再求下一层。每层的归一化尺度与容差必须记录在结果中；不声称数值计算具有无容差的严格字典序保证。

同优先级多个产物默认要求用户选择语义：

- 加权吞吐：按用户参考速率归一化后加权，可能集中生产一个产品。
- 固定配比：定义共同尺度 λ，约束各交付量等于 λ × 配比，再最大化 λ。

第一版优先实现固定配比与分优先级单目标；加权模式作为高级选项。显示单位改变时不得改变标准化后的目标。

任何阶段 unbounded，都停止后续优化并提示缺少有限瓶颈。不能用一个巨大隐含上界把无界问题伪装成最优解。

## 8. 结果、安装建议与 BOM

### 8.1 结果来源

- 外部输入：s。
- 产品交付：t。
- 排放：w。
- 端口毛吞吐：端口标准速率 × x，或对应分流器变量。
- 守恒残差：A_eq x − b_eq，仅用于校验。
- 容量余量：b_ub − A_ub x。

先按 Net 展示，再提供按资源汇总。汇总不能掩盖独立网络中的短缺和瓶颈。电力分别显示供给能力、实际发电、负荷和外部交换。

### 8.2 安装建议

将 `machines_exact` 更名为 `operating_equivalent`，安装建议记为 `recommended_installed`。

原则上推荐安装数为 ceil(x)。若 x 在经校验的数值容差内接近整数，可吸附到该整数，但需要确认容量偏差在允许范围内。不得用固定 epsilon 无条件扣减。

零运行量时安装建议为 0，利用率为 null；正运行量时利用率为 x / recommended_installed。

机器可按时间平均启停、没有不可忽略的固定负荷、没有启动限制时，该建议适用。否则显示相应限制。求解后的流量始终使用连续运行量，不用向上取整后的台数重算满载流量。

此结果不承诺最少整数安装台数或最小 CapEx。未来需要时引入安装整数变量 n_j，与运行量 x_j ≤ n_j 联动，并显式建模固定消耗与建厂成本。

### 8.3 BOM 与启动

BOM 按选定的安装方案汇总，区分每机器、每并行槽和全局一次性占用。没有启用的配方不自动计费；用户已固定安装的设备按实际固定数量计费。

Source 的机器造价只有在存在明确的“吞吐到安装数量”规则时才能计算，不能直接将流量作为机器数。

保留单独的启动清单：催化剂、种子库存、预热条件。检测到资源循环仅提示“需要确认启动条件”；第一版不声称通过机器数下界证明可启动。运行可行性与 startup_status 分开。

## 9. API 契约

### 9.1 POST /api/calculate 请求

请求包含：

```text
schema_version
request_id
document_revision
compiler_fingerprint
variables: [{ id, lower, upper }]
equalities: { row_ids, rhs, entries: [{ row, col, value }] }
inequalities: { row_ids, rhs, entries: [{ row, col, value }] }
objectives: [{ id, priority, coefficients, abs_tolerance, rel_tolerance }]
solver_options: { time_limit_ms }
```

coefficients 使用变量索引与数值组成的稀疏数组。后端按文档语义以外的通用规则执行 LP，不根据节点类型补建 Source、Spill 或修改目标。

节点、端口和 UI 来源映射由前端 IR 持有，后端返回稳定变量/约束 ID 即可关联。不得将颜色、画布位置等 UI 状态发送给求解器。

后端校验维度、索引、唯一 ID、重复项合并规则、数值有限性、上下界关系、非零元数量、目标层数和总时间预算。请求不能突破服务器配置的资源上限。

### 9.2 响应

```text
request_id, document_revision, compiler_fingerprint
status: optimal | infeasible | unbounded | limit_reached | invalid_model | solver_error
solution: 可选，包含变量值与可行性校验结果
objective_results: 每阶段的值、状态、耗时、是否证明最优
row_residuals, bound_slacks
diagnostics: 结构化原因和相关 row_id / variable_id
timings: queue_ms, solve_ms, total_ms
```

多阶段共用一个总预算。中途超时可返回上一阶段已验证可行的方案，但明确指出后续优先级尚未优化完毕；不得标记 optimal。没有可用方案时 solution 为空。

返回结果必须经过残差、变量边界与有限性检查。校验失败时不得当作成功展示。

## 10. 诊断与交互

### 10.1 求解前

优先给出用户可直接修复的错误：端口消失、单位不可换算、缺失供应、非法分流比、周期为零、修饰器依赖冲突、固定工况不满足。

用户明确禁用的节点可以排除，但其相关连线必须显式失效。资格不满足的节点不得静默消失，让其他资源意外变成免费供应。

### 10.2 不可行诊断

原模型 infeasible 后，在用户可见的诊断流程中建立弹性模型，对指定需求、容量、守恒行加入带单位归一化的松弛变量，求一个低违约量的解释方案。

显示“至少缺少矿石 5/s”“某副产物缺少 2/s 出口”等信息，并定位节点。只放松预先允许诊断的约束，不能任意破坏所有物理规则后输出无意义解释。

诊断方案只是一种冲突解释，不承诺唯一原因或最小不可行子集，也不能替换正式结果。

### 10.3 瓶颈

约束达到上限只标注“已满载”。要标注“增加此容量可改善目标”，需结合当前目标层的边际信息或做小幅容量扰动重算，并说明改善对应哪个目标。退化解与多阶段约束会影响解释，避免把单一边际值当作全局结论。

### 10.4 异步状态

编辑后旧结果标记过期。请求携带 document_revision；只接受与当前模型版本匹配的结果。合并快速连续编辑，取消未开始任务，运行中旧任务由后端时间预算约束。

拖动节点位置、缩放画布和切换显示单位不触发重新求解。改变标准化物理数值、连接或目标才改变模型指纹。

## 11. 性能与实现约束

1. 全链路使用稀疏系数；后端构建适配求解器的稀疏矩阵，不经稠密中间矩阵。
2. 缓存单节点修饰器和归一化结果。拓扑变化时重编译相关网络；第一版允许全量重编译拓扑，只要测量达到体验目标。
3. 求解任务进入有界执行池，避免阻塞 API 事件循环；限制线程与进程总并发，防止过度竞争。
4. 基准按变量数、约束数、非零元、系数跨度、目标层数、循环与退化程度记录。分别测量编译、传输、排队、求解和渲染。
5. 将原性能表改为待实测目标，至少报告指定硬件与固定数据集上的 P50/P95、峰值内存及并发行为。
6. 不用 SCC 贪心替代全局优化。只有在变量—约束关联图分离、目标可分离且不存在共享预算时，才考虑严格独立分块；多目标共享锁定条件也需要检查。
7. 任意可执行插件应视为独立的信任边界。第一版优先支持内置或明确受信的插件；超时与进程隔离不能被描述成完整的代码安全沙箱。

## 12. 分阶段实施

### 阶段 A：正确性核心

实现资源/端口/Net 身份、最终 IO 后编译拓扑、完整守恒、显式供应和排放、连续运行量、稀疏 LP 及正确结果汇总。

完成条件：下表涉及守恒、隔离、回代和边界的案例通过；没有任何隐式免费输入或隐式排放。

### 阶段 B：目标与诊断

实现目标分层、至少/恰好/最大化模式、状态码、模型版本校验、输入错误定位和弹性诊断。

完成条件：权重尺度反例不再破坏优先级，未完成求解不会显示为最优，旧响应不会覆盖新结果。

### 阶段 C：产品闭环

实现修饰器轨迹、安装建议、BOM、启动提示、固定比例分流器、容量利用率及性能基准。

完成条件：用户能够区分“平均运行方案”“安装清单”“启动待确认”和“真实阻塞”，并能从错误直接定位修改处。

MILP、库存时序、边容量和自动工况选择另立后续设计，不塞入第一版连续 LP 的隐含假设。

## 13. 最小验收案例

| 编号 | 输入情景 | 预期行为 |
|---|---|---|
| T01 | 配方输入未连接，产物有需求 | 编译报缺少来源，不免费生产 |
| T02 | 显式无限 Source | 允许供应，UI 显示无限外供假设 |
| T03 | 供给上限 5/s，硬需求 10/s | infeasible；诊断可定位至少 5/s 缺口 |
| T04 | 主产物有需求，必然副产物无出口且禁排 | infeasible，不能靠罚分通过 |
| T05 | T04 显式允许足量排放 | 可行，返回非零排放并显示出口 |
| T06 | 输入矿石 10/s，产出并交付铁板 10/s | 输入与交付均显示 10/s，残差接近零 |
| T07 | 两个独立 Net 使用同名资源，仅一个有供应 | 不跨 Net 借用资源 |
| T08 | 同节点加工水和冷却水连接不同 Net | 保留独立系数与来源 |
| T09 | 固定有限瓶颈，产品每 1/s 需要 20000 台运行量 | 产品优先级高于机器成本时仍最大化产出 |
| T10 | 微量副产物、改 L 为 mL 展示 | 单位显示变化不改变解；禁排始终禁排 |
| T11 | 修饰器新增/删除副产物端口 | 新端口进入编译；旧失效连线显式报错 |
| T12 | A→2A 闭环，无初始 A，运行目标有界 | 可报告稳态方案，同时启动条件待确认 |
| T13 | 40:60 分流，第二支路完全阻塞且禁排 | 整个分流器流量为零；硬需求可能不可行 |
| T14 | 运行量 1.2 台，允许线性启停 | 建议装 2 台、利用率 60%，物流按 1.2 台计算 |
| T15 | 源流量为 0.25/s | 保留 0.25，不取整 |
| T16 | 无限来源、无产能上限、最大化目标 | unbounded，不自动设置隐含大上限 |
| T17 | 普通产出同时有至少交付目标与额外副产物 | 不承诺 Demand 恰好交付；exact 模式严格等于指定值 |
| T18 | 发电能力 100，实际负荷 60，可调度 | 实际发电 60、剩余能力 40，不显示排放 40 |
| T19 | 自动安装且存在不可忽略的每安装机器固定负荷 | 要求固定安装数或显式近似，不冒充精确解 |
| T20 | 求解期间修改图，新响应先返回 | 旧响应不覆盖当前图结果 |
| T21 | 分层求解第一层完成、第二层超时 | limit_reached，保留已验证方案并说明未完成层 |
| T22 | 同变量同 Net 同时输入输出同一资源 | 净系数正确相加，UI 保留输入输出毛流量 |
| T23 | duration 为 0、NaN、非法索引或上下界倒置 | invalid_model 或前端编译错误，不调用求解器 |
| T24 | 未运行配方含零损耗催化剂 | 自动安装 BOM 不计该配方；已固定安装另按实际配置计费 |

这些案例首先作为产品与编译器的共同规格，再分别落为编译测试、模型测试和少量端到端验收，避免只验证实现细节而没有验证真实语义。
